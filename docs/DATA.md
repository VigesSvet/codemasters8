Какие наборы данных есть в системе, откуда они взяты, что в них есть и чего нет, как их загрузить и перегенерировать. Документ для жюри(требование ТЗ §8 "тестовые данные и способ их загрузки/генерации"), оператора развёртывания, разработчика и заказчика, если у него есть вопросы о происхождении данных и персональных данных.

## Стартовый набор

`shared/snapshot/` - реальные данные мониторинга Усть-Каменогорска. Публикации собраны подключениями 18.10.2026, набор выгружен 18.10.2026 в 22:43 UTC(19.10.2026 по местному времени), ответы офлайн-копии рассчитаны на 19.10.2026. Новое развёртывание стартует с этими данными, а не с пустыми экранами. Модуль - `backend/app/snapshot.py`.

`manifest.json` описывает набор: формат `saq-snapshot-1`, версию схемы БД выгрузки(`schemaVersion`: у набора в репозитории `2026.10-discovery-1`, у кода `2026.10-audit-2`), время выгрузки, строки и столбцы таблиц, сжатие изображений, что не вошло и почему, сверку записей реестра. В Git набор занимает 374 файла, около 34 МБ.

### Чего в наборе нет

Перечень задают `EXCLUDED` и `ALSO_EXCLUDED` в `snapshot.py`; `manifest.json` хранит перечень выгрузки, которой создан набор.

| Что | Почему |
|---|---|
| Видеофайлы и кадры видео | Объём; строка видео остаётся "недоступно" со ссылкой на оригинал, распознанный текст - в `ads.ocr`; у набора в репозитории не выгружены 923 строки кадров |
| Заявки жителей(`bot_submissions`) | Персональные данные заявителей |
| Предупреждения жителям, доставки, подписки | Сообщения конкретного развёртывания; подписки содержат `chat_id` |
| Токены подключений, состояния OAuth | Секреты |
| Задания и аренды воркера, счётчики квот и бюджета, `meta` | Состояние работы; версию схемы и флаги задаёт загрузка |
| Записи реестра(`source_records`) | Загрузка пересоздаёт их из `shared/registry_ust_kamenogorsk.json` |
| Кэш кандидатов 2ГИС | Остаются только решения аналитика |
| Состояние подключений | Статус, факты, курсоры, ошибки, расписание сбрасываются: новое развёртывание проверит подключения заново |
| События подключений в журнале; автор, ID и стоимость внешних запусков | Сведения администратора |
| Внешние ID заявок бота | Заменяются псевдонимами `tgbot#<24 hex>`(HMAC-SHA256 с ключом одной выгрузки, ключ не сохраняется) |

Тексты ошибок маскируются(`logs.redact`), снимки ответов источников повторно проходят `ingest.scrub`: без токенов, cookie, телефонов и e-mail в служебных полях, ссылки без query. У анализов ИИ не сохраняется request-id Anthropic.

Стартовый набор - не резервная копия рабочей БД: в нём нет токенов, заявок жителей, видео и служебных таблиц. Резервные копии - [DEPLOYMENT.md](DEPLOYMENT.md#резервные-копии).

Набор в репозитории выгружен при схеме `2026.10-discovery-1` и содержит строки, которые выгрузка текущим кодом не переносит: 7 событий подключений в журнале(настройка и проверка источников), автора запусков сбора, ID и стоимость запуска Apify у запуска TikTok и ID этого запуска у его 10 записей приёма. При загрузке эти события получают вид `connector` и видны только администратору([SECURITY.md](SECURITY.md#журнал-и-его-видимость)). Повторная выгрузка их убирает. Таблицы решений по "Проверке по рекламе"(`screening_decisions`) в этом наборе нет: её добавил более поздний шаг схемы, при загрузке она пустая, а повторная выгрузка включает её строки.

Набор содержит публичную рекламу третьих лиц - застройщиков и агентств, собранную для мониторинга рекламы долевого строительства. Оценки по ней - предварительная автоматическая оценка и гипотезы ИИ, не вывод о нарушении. Условия использования - [CREDITS.md](../CREDITS.md#стартовый-набор-данных). ## Загрузка и обновление стартового набора

### Автоматическая загрузка

При каждом старте API обновляет схему БД(`seed.init_db`) и вызывает `seed.start`:

1. БД пуста(нет строк ни в одной таблице набора) и набор есть - набор загружается; в лог API пишется строка "Пустая БД: загружен стартовый набор от ..." с числом строк, файлов и записей реестра.
2. БД пуста, набора нет - загружаются только реестр и карточки по нему; API предупреждает, что аналитиков для входа нет.
3. БД не пуста - набор не загружается никогда.
4. Затем всегда вызывается `demo.import_registry`([ниже](#карточки-из-реестра)); на свежем наборе он ничего не меняет.

Несовместимый или испорченный набор прерывает старт API с причиной в логе. Пустая БД - новый том `pgdata` в Docker или новая `backend/saq.db` при `./dev.sh`; как начать с чистого листа - [DEPLOYMENT.md, "Данные при развёртывании"](DEPLOYMENT.md#данные-при-развёртывании).

### Загрузка вручную

```bash
docker compose exec -T api python -m app.snapshot import                 # набор из образа
docker compose exec -T api python -m app.snapshot import --dir /путь     # другой каталог
cd backend && DATABASE_URL=sqlite:///./saq.db .venv/bin/python -m app.snapshot import   # локально
```

Непустую БД команда не меняет вовсе(проверка идёт до обновления схемы): код выхода 2. Тот же код - если нет `manifest.json` или набор несовместим.

Порядок загрузки(одинаков у автоматической и ручной):

- одна транзакция; на PostgreSQL - под advisory lock обновления схемы;
- таблицы в порядке внешних ключей с прежними первичными ключами; последовательности PostgreSQL переставляются за максимальный `id`;
- файл таблицы - только `<таблица>.json` в каталоге набора, число строк сверяется с `manifest.json`;
- изображения пишутся в `MEDIA_ROOT` через `media.store_bytes`: тип по сигнатуре, SHA-256 и ключ сверяются с записью, ссылки и не обычные файлы отклоняются;
- записи реестра пересоздаются из JSON реестра;
- ставится флаг `meta.demo_data = purged`.

**Совместимость.** Загружается набор текущей или любой прежней версии схемы из цепочки `backend/app/migrate.py`: недостающие столбцы получают NULL или значение по умолчанию, таблицы более поздних шагов остаются пустыми, строки проходят переводы данных этих шагов(события подключений вида `data` становятся `connector`). Неизвестная или более новая версия, лишний или недостающий обязательный столбец - отказ: набор нужно выгрузить заново.

После загрузки:

- Подключения - с настройками и отметкой "включено", в статусе "не проверено"; ключи - только из `.env` нового сервера([INTEGRATIONS.md](INTEGRATIONS.md)). Повторный сбор не дублирует публикации: они уникальны по паре площадка и внешний ID.
- Ответов текущей версии промпта(`saq-llm-3`) в наборе нет: с `ANTHROPIC_API_KEY` воркер дозапрашивает их в пределах дневного бюджета, до этого показывается ответ прежней версии([AI.md, "Анализ Claude"](AI.md#анализ-claude)).

### Выгрузка набора

```bash
make snapshot-export-docker   # PostgreSQL и том media стека Docker -> shared/snapshot(стек запущен: make up)
make snapshot-export          # DATABASE_URL(по умолчанию SQLite ./dev.sh) и MEDIA_ROOT -> SNAPSHOT_DIR
```

Без make локально - `cd backend && DATABASE_URL=sqlite:///./saq.db .venv/bin/python -m app.snapshot export`. Для Docker та же команда идёт в контейнере образа `api` с подключёнными `backend/` и `shared/`(текст - цель `snapshot-export-docker` в `Makefile`): файлы лежат в томе `media`.

Параметры: `--out`(по умолчанию `shared/snapshot`), `--max-px`(16-10000, по умолчанию 1024), `--quality`(1-100, по умолчанию 75). Отказ - код выхода 2.

- **Только чтение.** БД читается одной транзакцией(PostgreSQL - `REPEATABLE READ, READ ONLY`, SQLite - явный `BEGIN`): запись воркера во время выгрузки не даёт несогласованного набора. Схема не обновляется; выгружаются столбцы, общие для модели и БД.
- **Стабильный формат.** Строки по первичному ключу, ключи по алфавиту, время в ISO 8601 UTC.
- **Ответы API** строит отдельный процесс на временной SQLite тем же кодом, что у нового развёртывания, без секретов в окружении.
- **Проверка на секреты.** Все `*.json` проверяются на значения секретов из настроек и токеноподобные строки(ключи Anthropic, Apify, Meta, токены Telegram-бота, Bearer, подписанные ссылки и другие), `ingest_items.json` - ещё на ID заявок бота без псевдонима. Найдено - набор не записывается.
- **Замена целиком** и только при полном успехе. Заменить можно только прежний набор или пустой каталог: опечатка в `--out` не удалит чужие файлы.
- **Сверка реестра.** Записи реестра в БД сверяются с JSON, итог - раздел `registry` в `manifest.json`. Расхождение(например, после импорта на `/sources`) - предупреждение и `consistent: false`. Новое развёртывание возьмёт записи из JSON, поэтому сначала перегенерируйте его.

### Только ответы API

`make snapshot-views` пересчитывает `api/*.json` по строкам набора на дату `api.asOf`, без выгрузки из БД. Нужна после изменения кода риска или "Проверки по рекламе": об этом напоминает `test_offline_views_match_api`(`backend/tests/test_snapshot.py`). `api/media.json` и список файлов в `manifest.json` цель не переписывает, поэтому новый вид ответа требует полной выгрузки.

### Нормализация и провенанс

- Пустая ячейка - `null`; значения не дополняются и не оцениваются.
- Даты - в ISO, время сбора - в UTC, дата загрузки у поставщика - как у поставщика.
- БИН - 12 цифр; готовность - от 0 до 100; ссылки - только http(s).
- Способ привлечения - код `guarantee`, `mio` или `bvu` и исходный текст; нераспознанный - только текстом.
- Координата "0" - координат нет; неполная или недопустимая пара не сохраняется; дальше 30 км от центра города - сохраняется с предупреждением.
- Строка неизвестного источника или без обязательных полей пропускается; повтор пары "источник + ID в источнике" - остаётся первая.

Провенанс записи: `source`(код), `sourceName`(подпись как в файле), `sourceSection`, `sourceUrl`, `sourceRecordId`(до 64 символов), `collectedAt`(UTC), `providerLoadedAt`, а в БД ещё `importedAt`, `importFile`, `row` - когда, из какого файла и строки запись загружена.

### Объекты

Записи группируются по нормализованному названию: без "ЖК", "МЖК", кавычек, регистра, "блок А", "пятно N", "очередь N", "здание N", "корпус N", "(ГС: ...)". Ключ объекта - латинский slug(`zhanym`, `zolotoi-kvadrat`). Основная запись: Homeportal важнее Казреестра, с координатами важнее, без "блок/очередь" важнее.

Из 103 записей - 15 объектов. Без координат у источника - `ab-residence-2`, `diamond`, `prestizh-sparkle-diamond`. У `renesans` координаты источника в 188 км от центра города: они сохранены как есть с пометкой `flags.coordsFarKm`, но на карту объект не ставится(`onMap` в `frontend/src/lib/provenance.ts`), поэтому в слое "Открытые данные" на карте 11 серых меток. У `ab-residence-2` пометка `flags.sourceSection` - "Без разрешения на дольщиков".

Где видно: `/complexes?layer=open` - список объектов с разделом "Без координат", переключатель "Открытые данные" на карте, `/registry/:key` - объект со всеми записями, `/sources` - источники, импорт и подключения([FEATURES.md, "Реестр и карточка ЖК"](FEATURES.md#реестр-и-карточка-жк)). Без бэкенда фронтенд показывает встроенную копию JSON реестра(`frontend/src/data/openData.ts`, отдельный чанк) с теми же объектами и записями; импорт в этом режиме недоступен.

### Перегенерация JSON реестра

Образ видит только `shared/`, поэтому нормализованный набор хранится как `shared/registry_ust_kamenogorsk.json`: метаданные сборки(файл, лист, SHA-256, время, период сбора, отчёт), источники, записи и объекты списками `objects` и `withoutCoords` - в форме `GET /api/registry`. Пересобирается локально:

```bash
cd backend && .venv/bin/python -m app.importer ../docs/Усть-Каменогорск_объекты.xlsx            # пишет shared/registry_ust_kamenogorsk.json
cd backend && .venv/bin/python -m app.importer ../docs/Усть-Каменогорск_объекты.xlsx --dry-run  # только отчёт
```

`--out` - другой путь вывода. Команда печатает отчёт и замечания по строкам; файл не разобран - код выхода 2. `test_registry.py` проверяет, что JSON совпадает с xlsx и с ответом API.

Новый JSON сам в существующую БД не попадает: из файла загружаются только БД без записей реестра и загрузка набора. В рабочую БД файл загружают импортом на `/sources`.

### Импорт через интерфейс

Страница `/sources`(только с бэкендом) вызывает `POST /api/sources/import`: multipart с полем `file`, автор - поле `author` или `?author=`, без него "Система". Парсер тот же, что у команды.

- **Форматы:** `.xlsx`(первый лист со строкой заголовка) и `.csv` в UTF-8(BOM допустим); разделитель "," или ";" определяется по заголовку. Недостающие колонки пусты, неизвестные пропускаются с предупреждением.
- **Сверка** по паре "источник + ID в источнике": новые добавляются, изменившиеся обновляются, остальные - "без изменений".
- **Отчёт** в ответе и событие журнала вида `data` с автором и числами новых, обновлённых, неизменных и пропущенных записей.
- **Пределы:** файл больше 5 МБ - 413(тело больше 5 МБ с запасом 64 КБ на разметку multipart отклоняется по `Content-Length` до чтения, точный размер проверяет разбор); не `.xlsx` и не `.csv`(в том числе `.xls`) - 415; больше 64 МБ после распаковки, повреждённый или пустой файл, CSV не в UTF-8, нет заголовка, больше 20 000 строк - 422; параллельный импорт тех же записей - 409.

Форматы ответов - [API.md, "Открытые данные"](API.md#открытые-данные). Автоматической синхронизации с Homeportal, Казреестром и Ashyq Data нет: записи появляются только из файла.

## Карточки ЖК из реестра и по рекламе

Аналитик работает с карточками ЖК: у объектов реестра это карточки `origin = registry`, у ЖК, которых в реестре нет, но которые называет реклама, - `origin = advertised`. Формальный риск по ним не оценивается, пока нет проверенных сведений: [RISK_MODEL.md, "Риск не оценивается"](RISK_MODEL.md#риск-не-оценивается).

### Карточки из реестра

Создаёт и дополняет `demo.import_registry`(`backend/app/demo.py`) при каждом старте API и командой `python -m app.demo import-registry`. Если записей реестра в БД нет, сначала загружает их из JSON с событием журнала.

- **ID:** ЖК - `r-<ключ объекта>`(длинный ключ - `rh-<sha1>`), застройщик - `rd-<БИН>`(без БИН - `rd-<sha1 названия>`). Объект без застройщика пропускается с причиной.
- **Из источника:** название без обёртки "ЖК "..."", адрес без города, координаты, застройщик. Начало и плановое завершение - только если записи объекта согласны; завершение - только у строящегося по источнику объекта.
- **Нет сведений:** стадия, готовность и основание. "В строительстве" и "Завершён" у источника - фильтр, а не стадия, применимость документа к очереди нужно проверять. Номера документов - справкой в `guaranteeRef`, `mioRef`, `bank` с пометкой "Аналитиком не проверено".
- **Без координат** карточка тоже создаётся; точку выбирают сверкой в 2ГИС.
- **Повтор идемпотентен:** дополняются только пустые поля, координаты и справки; правки аналитика не перезаписываются. ID занят ЖК другого происхождения - пропуск с причиной.
- **Журнал:** событие `data` от "Системы" о каждой созданной и дополненной карточке.

Основание по открытым данным карточка получает в [RISK_MODEL.md, "Проверка по рекламе"](RISK_MODEL.md#проверка-по-рекламе).

### Карточки по рекламе

- **Из объекта рекламы** - аналитик, `POST /api/discovered/{oid}/create-complex`([FEATURES.md](FEATURES.md#проверка-по-рекламе-и-объекты-из-рекламы)).
- **Списком через API** - `POST /api/discovered/import` с телом `{author, note?, items}`, до 200 строк, с токеном администратора.
- **Списком из консоли** - `python -m app.demo add-advertised --file x.json [--author ИМЯ] [--note ТЕКСТ]`; файл - список строк или `{"note", "items": [...]}`.

```json
{"name": "ЖК Nova Park", "aliases": ["Нова Парк"], "address": "ул. Абая, 10", "lat": 49.95, "lng": 82.6,
 "developerName": "ТОО Nova Build", "developerBin": "123456789012", "accounts": ["@novapark.uka"],
 "sourceUrls": ["https://www.instagram.com/p/..."], "note": "..."}
```

Обязательно только `name`(пример вымышленный); координаты - парой; ссылки не http(s) отбрасываются; неизвестные поля отклоняются.

- **ID:** ЖК - `a-<латинский ключ названия>`, длинный, пустой или занятый - `ah-<sha1>`; застройщик - `ad-<БИН>` или `ad-<sha1 названия>`.
- **Застройщик:** существующий по БИН, затем по названию без формы собственности(но не с другим БИН); иначе новый `advertised`; без названия и БИН - заглушка `ad-unknown` "Застройщик не установлен".
- **Идемпотентность по ключу названия:** у существующей карточки `advertised` дополняются только пустые адрес и координаты, другие названия, аккаунты и ссылки.
- ЖК из реестра или справочника пропускается с причиной. Объект рекламы с тем же названием привязывается к карточке, правила сопоставления его публикаций пересчитываются без запроса к Claude. О каждой карточке - событие журнала.

Восемь карточек `a-...` стартового набора созданы таким импортом.

## Происхождение записей

Поле `origin` есть у ЖК, застройщиков, публикаций, обращений и записей реестра, в ответах API - и у объектов реестра. Допустимые значения - тип `Origin` в `backend/app/schemas.py`.

| Значение | У кого | Что значит | Метка в интерфейсе |
|---|---|---|---|
| `analyst` | Публикации, обращения | Внесено аналитиком: публикация через форму(`source = manual`), обращение при сверке | "Добавлено аналитиком", вид "Решение аналитика" |
| `collected` | Публикации | Подключение или приём API(`source = parser`), заявка жителя через бота(`source = bot`) | "Собрано из источника" или "Прислано жителем через бота", вид "Факт из источника" |
| `registry` | ЖК, застройщики | Карточка по открытому реестру, не проверена | "Открытый реестр" |
| `advertised` | ЖК, застройщики | Известен только по рекламе, не проверен | "По рекламе" |
| `source` | Записи и объекты реестра | Сведения источника как есть, со ссылкой и временем сбора | "Факт из источника" |
| `demo` | ЖК, застройщики, публикации, обращения | Вымышленный демо-набор: тестовые данные и базы прежних версий | "Демонстрационные данные" |

Вывод ИИ хранится отдельно и помечается "Гипотеза ИИ", пока аналитик его не примет. Решения аналитика(привязка, сверка документа, "Объект сдан", "Проверено - замечаний нет") помечаются "Решение аналитика" с автором и временем. Подписи - `frontend/src/components/Provenance.tsx` и `frontend/src/lib/provenance.ts`.

У объектов из рекламы своё поле `origin`: `ads` - найден в ответе Claude, `import` - создан импортом карточек по рекламе.

В БД со стартовым набором записей `demo` нет. Если они остались в базе прежней версии, API при старте предупреждает; удаление - [DEPLOYMENT.md, "Базы с прежним демо-набором"](DEPLOYMENT.md#базы-с-прежним-демо-набором).
