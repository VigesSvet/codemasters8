# Подключения и внешние сервисы

Источники публикаций и внешние сервисы SAQ Qurylys: что собирает каждое подключение, как его включить и проверить, переменные, лимиты и расходы, статусы и ошибки. Здесь же контракты приёма публикаций и Telegram-бота заявок и отправка предупреждений жителям через Telegram Bot API. Документ для оператора(администратора подключений), владельца аккаунтов источников, разработчика подключений и жюри.

Полная таблица переменных - [DEPLOYMENT.md, "Переменные окружения"](DEPLOYMENT.md#переменные-окружения).

## Обзор подключений

Коды - из `backend/app/integrations/registry.py`, они же аргументы `app.integrations.smoke`; порядок - как в разделе "Подключения" страницы `/sources`.

| Код | Что даёт | Способ | Стоимость | Что нужно | Вживую |
|---|---|---|---|---|---|
| `instagram` | Публикации профессиональных аккаунтов из списка | Meta Graph API, Business Discovery | лимиты Graph API | токен Meta | да |
| `telegram` | Сообщения публичных каналов, альбомы, правки | MTProto(Telethon), выделенный аккаунт | бесплатно | `TG_API_ID`, `TG_API_HASH`, вход по коду | нет |
| `tiktok` | Публикации профилей, обложки, видео | Apify, Actor `clockworks/tiktok-scraper` | платно | `APIFY_TOKEN` | да |
| `krisha` | Объявления выдачи и карточки Krisha.kz | HTML-сборщик | бесплатно | URL поиска в настройках | да |
| `telegram_bot` | Заявки жителей с фото и видео | приёмник `POST /api/intake/telegram` | бесплатно | `SERVICE_API_TOKEN`, бот | нет |
| `intake` | Публикации внешних сборщиков | приёмник `POST /api/intake/publications` | бесплатно | `INTEGRATION_INGEST_TOKEN` | да |
| `dgis` | Кандидаты адреса и координаты | 2ГИС Catalog API 3.0, `items/geocode` | квота ключа | `DGIS_API_KEY` | да |
| `anthropic` | Гипотезы ИИ по тексту и OCR | Anthropic Messages API | платно, дневной бюджет | `ANTHROPIC_API_KEY` | да |
| `olx` | Свой аккаунт OLX, без чужих объявлений | OLX Partner API, OAuth | бесплатно | одобренная заявка, ключи OLX | нет |

Вне раздела "Подключения" и без кода `smoke` работают [фото Homeportal](#фото-homeportal) и [предупреждения жителям](#предупреждения-жителям-через-bot-api) через Bot API(только отправка).

```text
Instagram, Telegram-каналы, TikTok, Krisha.kz -> воркер: задания "проверка" и "сбор"(кнопка или расписание)
Бот заявок -> POST /api/intake/telegram;  внешний сборщик -> POST /api/intake/publications
  -> единый приём: дедупликация по(площадка, внешний ID), версии, файлы -> БД и MEDIA_ROOT
  -> задание анализа: media -> frames -> speech -> ocr -> rules(saq-ai-1) -> llm(Claude) -> events
  -> публикация "Новая", гипотезы ИИ -> решение аналитика -> балл -> сигнал
2ГИС -> кандидаты адреса -> выбор аналитика;  OLX -> OAuth своего аккаунта;  Homeportal -> фото ЖК
Предупреждение -> согласование -> задание "alert" -> Bot API
```

Этапы анализа - [AI.md, "Конвейер анализа публикации"](AI.md#конвейер-анализа-публикации).

## Принципы сбора

- **Подготовка не равна работе.** Успешная интеграция - новый материал из источника, сохранённый с доказательствами(текст, файлы, исходный ответ, время, ссылка) и доступный аналитику; ключ или удачная проверка - только подготовка.
- **Ошибка источника - статус, а не пустая выдача.** Неверный ключ, закрытый канал, изменившаяся разметка, запрет robots.txt, проверка доступа дают ошибку с пояснением; "нет новых" - только запуск без ошибок и без записей.
- **Сбор выполняет только воркер**(`python -m app.worker`): проверки, сбор, анализ, расписание. "Проверить подключение" и "Собрать сейчас" ставят задание и отвечают 202 с номером запуска(200 - такое задание уже в очереди или выполняется).
- **Собранная публикация - не решение.** Статус "Новая", `origin = collected`, `source = parser` или `bot`, без привязки к ЖК: анализ предлагает ЖК, решает аналитик(`SAQ_COLLECTED_AUTOLINK=1` - привязка-гипотеза для демонстрации). Автор автоматических событий журнала - "Система".
- **Защиты сайтов не обходятся.** robots.txt соблюдается; проверка доступа(CAPTCHA, SafeLine) останавливает сбор до ручного действия, без подмены браузера, решения проверок и прокси.
- **Границы мониторинга.** Сбор аккаунтов и каналов из списка не видит персонализированных рекламных показов; их дополняют заявки жителей через бота.

## Статусы подключения и запуска

Подписи - `STATUS_LABELS` в `backend/app/integrations/base.py`, свои подписи у OLX и [Claude](#claude).

| Статус | Что значит | Что делать |
|---|---|---|
| не настроен | Нет переменных(в карточке - их имена) или сессии Telegram | Заполнить `.env`, перезапустить API и воркер |
| не проверен | Проверки не было или ключи изменились после неё | "Проверить подключение" |
| в очереди, проверяется, идёт сбор | Задание ждёт воркер или выполняется | Долго "в очереди" - проверить воркер |
| готов к сбору(у 2ГИС и Claude - "готов") | Проверка прошла | Настроить, собрать |
| работает(у приёмников - "принимает заявки", "принимает публикации") | Последний сбор успешен | - |
| работает частично | Часть данных недоступна: закрытый канал, карточки Krisha за проверкой доступа, окно выдачи TikTok, предел первой загрузки Instagram | Заметки запуска |
| ожидает заявок, ожидает публикаций | Приёмник настроен, за 7 дней данных не было | - |
| ошибка | Сбой источника, ошибка настроек, отклонённая заявка | Текст - в карточке и журнале |
| истёк доступ | Истёк токен(Meta, OLX) или ключ отклонён | [Instagram](#instagram), [OLX.kz](#olxkz) |
| нет доступа | Нет разрешений или неверный токен клиента приёма либо бота | Проверить разрешения и токены |
| нужно ручное действие | Сайт закрыл страницы проверкой доступа | [Krisha.kz](#krishakz) |
| пауза: лимит запросов | Graph API, FloodWait, 2ГИС; у Claude - "пауза: лимит"(исчерпан дневной бюджет) | Ждать указанного времени |
| не используется | Claude: `ANTHROPIC_DAILY_BUDGET_USD = 0`, анализ ИИ выключен | Задать бюджет больше нуля |
| остановлен(метка) | Платный сбор после ошибки или ошибка настроек: расписание не запускает сбор | Исправить; успешная проверка снимает метку |

Подписи OLX: "заявка отправлена" - ключей нет; "не подключён" - OAuth не пройден; "подключено · ограничено" - аккаунт подключён.

Статусы запуска: в очереди, выполняется, успешно, частично, ошибка, проверка доступа на сайте, пауза: лимит запросов, не настроен, отменён.

Сменился ключ после успешной проверки(по отпечаткам) - карточка просит перезапустить воркер и проверить заново, расписание до этого не работает. Нет пульса воркера 120 с - страница пишет "Воркер сбора не запущен - проверки и сбор стоят в очереди"([DEPLOYMENT.md, "Воркер"](DEPLOYMENT.md#воркер)).

## Общая настройка

1. Ключи - в `.env` в корне по образцу `.env.example`; правила значений - [DEPLOYMENT.md, "Переменные окружения"](DEPLOYMENT.md#переменные-окружения). Значения ключей не уходят в интерфейс, ответы API и журналы: карточка называет только имена недостающих переменных - [SECURITY.md, "Секреты"](SECURITY.md#секреты).
2. Перезапуск: настройки читаются при старте процесса. Docker - `docker compose up -d api worker`, локально - перезапуск `make dev`(`./dev.sh`).
3. `/sources` → "Подключения" → "Режим администратора" → "Проверить подключение" → "готов к сбору".
4. "Настроить": списки источников(до 50 элементов по 255 символов, если не сказано иное) и "Период сбора, минут".
5. "Собрать сейчас" или "Сбор по расписанию".

### Режим администратора

- "Режим администратора" просит `SAQ_ADMIN_TOKEN` и проверяет его на сервере(`GET /api/admin/check`). Токен хранится в `sessionStorage` вкладки и уходит заголовком `X-Admin-Token` только в маршруты администратора; вход аналитика этих прав не даёт.
- Действия карточки: "Проверить подключение", "Настроить", "Сбор по расписанию", "Собрать сейчас", у OLX - подключение и отключение аккаунта. "Обновить всё" ставит сбор включённым, настроенным и проверенным сборщикам, остальные пропускает с причиной.
- Без `SAQ_ADMIN_TOKEN` на сервере маршруты администратора отвечают 503, без токена в запросе - 401, с неверным - 403.
- Без токена видны только статусы, расписание и счётчики; пояснения, ошибки, настройки и события журнала вида `connector` - только администратору.

Маршруты: состояние - `GET /api/sources/connectors`, настройки - `PATCH /api/sources/{code}`, проверка и сбор - `POST /api/sources/{code}/test` и `/collect`, "Обновить всё" - `POST /api/sources/collect-all`, запуски - `GET /api/collection-runs`. Из консоли - тот же заголовок или `Authorization: Bearer`([API.md, "Подключения и сбор"](API.md#подключения-и-сбор)):

```bash
curl -s -X POST http://127.0.0.1:8000/api/sources/krisha/test \
  -H "X-Admin-Token: <SAQ_ADMIN_TOKEN>" -H "Content-Type: application/json" -d '{"author": "Имя аналитика"}'
```

### Проверка из консоли

Модуль `app.integrations.smoke` проверяет подключения без интерфейса и БД(цели make нет):

```bash
cd backend && .venv/bin/python -m app.integrations.smoke               # все подключения
cd backend && .venv/bin/python -m app.integrations.smoke dgis krisha   # выбранные
docker compose exec worker python -m app.integrations.smoke            # Docker: сессия Telegram - у воркера
```

- Печатает "код: статус - пояснение" и несекретные сведения, без значений ключей; без ключей сеть не используется. Публикации не сохраняются, но запросы настоящие: 2ГИС расходует квоту в кабинете(локальный счётчик этот запрос не учитывает), Krisha получает обычные запросы, Apify - только чтение аккаунта и цен Actor, Anthropic - только `models.retrieve`.
- Для приёмников(`intake`, `telegram_bot`) печатается только, заданы ли ключи.
- Код выхода 0 - отчёт напечатан(это не тест), 2 - неизвестный код.

## Instagram

Meta Graph API, Business Discovery: публикации профессиональных аккаунтов из списка, запросы к `graph.facebook.com/{META_GRAPH_VERSION}/`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `META_USER_ACCESS_TOKEN` | - | Долгосрочный токен пользователя или системного пользователя, обязательна |
| `META_APP_ID`, `META_APP_SECRET` | - | По желанию: срок токена проверяется токеном приложения(без них - самим токеном), к запросам добавляется `appsecret_proof` |
| `META_GRAPH_VERSION` | `v26.0` | Версия Graph API |
| `META_IG_USER_ID`, `META_PAGE_ID`, `META_BUSINESS_ID` | - | Свой Instagram: по ID, иначе по Страницам токена, иначе по бизнес-портфолио; значения проекта - в `.env.example` |
| `IG_PAGE_SIZE` | 25 | Публикаций на запрос |
| `IG_FIRST_LOAD_MAX` | 50 | Предел публикаций аккаунта за запуск при первой загрузке |

### Токен Meta

1. [Graph API Explorer](https://developers.facebook.com/tools/explorer/) под аккаунтом с ролью в приложении и на Странице: приложение проекта, "User Token".
2. Разрешения: обязательные `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`; рекомендуемые `pages_show_list`, `business_management`(без них Страница находится только по `META_IG_USER_ID` или `META_BUSINESS_ID`). Роль на Странице через Business Manager требует ещё `ads_read` или `ads_management`.
3. Токен из Explorer живёт около часа. [Access Token Debugger](https://developers.facebook.com/tools/debug/accesstoken/) → "Extend Access Token" даёт долгосрочный, около 60 дней. Обмен на сервере, без ввода App Secret в браузер: `GET /oauth/access_token?grant_type=fb_exchange_token&client_id=…&client_secret=…&fb_exchange_token=…`. Альтернатива - токен системного пользователя.
4. Токен - в `META_USER_ACCESS_TOKEN`, перезапуск, "Проверить подключение": "Подключено: @… Токен действует до ДД.ММ.ГГГГ".
5. "Настроить" → "Аккаунты": `@имя` или `instagram.com/имя`. Расписание - по умолчанию раз в час, от 30 минут до суток.

**Продление.** Пока сбор включён, воркер раз в сутки проверяет токен(`debug_token`) и за 7 дней до истечения пишет "Токен истекает ДД.ММ.ГГГГ - продлите его", а при скором окончании доступа к данным - "Доступ к данным истекает ДД.ММ.ГГГГ - пройдите вход Meta заново"; продление - шаги 1-4. С токеном, истекающим в ближайшие сутки, сбор не включается: "Токен Meta краткосрочный - получите долгосрочный(60 дней) или токен системного пользователя". Истёкший или отозванный токен - "истёк доступ".

**Поведение.**

- Токен - только в заголовке `Authorization: Bearer`; страницы - по курсору, а не по ссылке `paging.next`.
- Файлы скачиваются при сборе и только с CDN Instagram и Facebook: ссылки на них временные.
- Карусели - со слайдами, видео - с обложкой; если Business Discovery слайдов не отдаёт, сохраняется первое изображение с заметкой.
- Первая загрузка идёт вглубь, пока страница вся новая, но не дальше `IG_FIRST_LOAD_MAX`, иначе запуск "частично". Прерванный обход продолжается без пропусков и дублей.
- При использовании лимита Graph API от 80% запуск прекращает запросы, следующий - через час. Нет разрешения - "нет доступа".
- Аккаунт, которого нет или который не профессиональный, - ошибка записи; если так со всеми - ошибка настроек.

## Telegram-каналы

MTProto через Telethon от выделенного аккаунта, только публичные каналы. `BOT_TOKEN` для чтения каналов не подходит.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TG_API_ID`, `TG_API_HASH` | - | [my.telegram.org](https://my.telegram.org) → "API development tools" выделенного аккаунта |
| `TG_PHONE` | - | Номер аккаунта, только для входа |
| `TG_SESSION_PATH` | `backend/data/private/telegram.session` | Файл сессии; в Docker - на томе `tgsession` только у воркера |
| `TG_HISTORY_LIMIT` | 50 | Сообщений канала в первый запуск |
| `TG_EDIT_WINDOW` | 30 | Правки отслеживаются среди стольких последних сообщений; 0 - не отслеживаются |
| `TG_MAX_VIDEO_MB` | 50 | Видео больше предела не загружается |
| `TG_DOWNLOAD_TIMEOUT_S` | 300 | Предел загрузки файла, секунд |

### Вход по коду

Вход выполняется один раз модулем `app.integrations.telegram_login`(цели make нет). Сессией пользуется один процесс(блокировка `<путь>.lock`), поэтому воркер на время входа останавливают. Код приходит в Telegram или SMS и действует 15 минут; его не пересылают сообщением в Telegram - такой вход может быть отклонён.

```bash
cd backend      # локально: ./dev.sh остановлен или запущен с SAQ_WORKER=0
.venv/bin/python -m app.integrations.telegram_login --send-code    # запросить код
.venv/bin/python -m app.integrations.telegram_login --code 12345   # войти; "-" - код из stdin
.venv/bin/python -m app.integrations.telegram_login --password     # если нужен пароль 2FA
.venv/bin/python -m app.integrations.telegram_login --status       # "Сессия есть: @имя"
```

В Docker - те же флаги через `docker compose run --rm worker python -m app.integrations.telegram_login …` между `docker compose stop worker` и `docker compose up -d worker`. Без аргументов вход идёт в одном запуске с вводом в терминале. Ещё флаги: `--force`(с `--send-code` - войти заново при существующей сессии), `--password-stdin`, `--logout`(выйти и удалить файл сессии). Коды выхода: 0 - готово; 1 - ошибка; 2 - не заданы `TG_API_ID`, `TG_API_HASH`, `TG_PHONE`; 3 - нужен пароль 2FA; 4 - неверный код или пароль; 5 - код устарел; 6 - Telegram просит подождать; 7 - сессия занята. Номер, код и сессия не печатаются.

Файл сессии - секрет: 0600 в каталоге 0700, не в Git и не в резервные копии; при потере проще войти заново. О сессии сообщает воркер, API её не видит.

### Сбор каналов

"Настроить" → "Каналы": `t.me/имя`, `@имя` или ссылка; ссылки-приглашения отклоняются. Расписание - по умолчанию раз в 30 минут, от 15 минут до суток.

- Первый запуск - последние `TG_HISTORY_LIMIT` сообщений, дальше - новые после позиции(до 500 за запуск) и правки в окне `TG_EDIT_WINDOW`. Позиция сохраняется после каждой публикации, перезапуск не создаёт дублей.
- Альбом - одна публикация, внешний ID - "{ID канала}:{ID первого сообщения}". Не скачавшийся файл повторяется, до трёх попыток.
- FloodWait - "пауза: лимит запросов"; сбой серверов Telegram - повтор задания.
- Закрытый или несуществующий канал - "частично" с причиной; недоступны все - ошибка настроек.
- Исходный ответ сохраняется белым списком полей: объекты Telethon - не JSON.

## TikTok через Apify

Actor `clockworks/tiktok-scraper` на Apify, платно. Ключи TikTok Developer не нужны.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APIFY_TOKEN` | - | API-токен Apify Console(Settings → API & Integrations) |
| `APIFY_ACTOR_ID` | `clockworks~tiktok-scraper` | Actor |
| `APIFY_MAX_TOTAL_CHARGE_USD` | 0.5 | Лимит расходов на запуск, USD |
| `APIFY_DAILY_BUDGET_USD` | 1.0 | Лимит на сутки по Усть-Каменогорску, USD |
| `APIFY_MAX_ITEMS_PER_PROFILE` | 5 | Публикаций с профиля за запуск |
| `APIFY_RUN_TIMEOUT_S` | 300 | Срок запуска, затем запуск прерывается |

Input без секретов - `backend/app/integrations/tiktok_input.json`; профили и число публикаций подставляются из настроек.

**Защита от расходов.**

- Лимит на запуск передаётся Apify как задан и не повышается; меньше минимума Actor или больше дневного лимита - ошибка настроек.
- Дневной лимит учитывает неудачные оплаченные запуски, а запуски с неизвестной стоимостью - по лимиту на запуск.
- После неповторяемой ошибки, исчерпанных повторов(3 попытки) и HTTP 402 платный сбор останавливается до успешной ручной проверки.
- Повтор задания не начинает второй платный запуск; потерянный ответ на старт - "запуск мог начаться", без повтора и с остановкой платного сбора.
- Расписание Apify(Schedule) не создают: запускает только воркер, иначе сбор оплачивается дважды.

**Настройка.** Токен в `.env`, перезапуск, "Проверить подключение"(без платного запуска), "Настроить": "Профили" - `@имя` или `tiktok.com/@имя`, до 20; "Публикаций за запуск с каждого профиля" - 1-50, но не больше `APIFY_MAX_ITEMS_PER_PROFILE`; "Загружать видео" - кадры для OCR и речь, каждое видео увеличивает расход. Расписание - по умолчанию раз в сутки, от 6 часов до недели.

**Поведение.**

- Запуск, опрос, чтение Dataset и подсчёт стоимости - фазы одного задания; позиция в Dataset сохраняется после каждой записи, недоступный Apify ждут не дольше часа.
- Файлы - только из хранилища Apify(Key-value store на `api.apify.com`) с Bearer-токеном, не с CDN TikTok. Видео режется на кадры для OCR, речь распознаётся локально - [AI.md, "Речь в роликах"](AI.md#речь-в-роликах).
- Флаги `isAd` и `isSponsored` публикации не отсеивают.
- Все полученные публикации ранее собранного профиля новые - часть могла выпасть из окна выдачи, запуск "частично".
- Стоимость запуска(в его карточке) - наибольшее из отчёта Apify(`usageTotalUsd`), событий по ценам Actor и оценки.

## Krisha.kz

HTML-сборщик выдачи. API у Krisha нет, ключи не нужны: подключение сразу "настроено".

**Настройка.** "URL поиска" - до 5 ссылок `https://krisha.kz/prodazha/…` или `/arenda/…`; по желанию "Карточки объявлений" - до 10 ссылок `https://krisha.kz/a/show/<id>`. Без URL поиска сбор - ошибка "Добавьте URL поиска Krisha"; проверка без настроек берёт выдачу по Усть-Каменогорску. Расписание - по умолчанию раз в 6 часов, от 2 часов до недели.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KRISHA_MIN_DELAY_S` | 5 | Пауза между запросами плюс случайные 0-2 с; больший `Crawl-delay` из robots.txt учитывается, но не больше 60 с |
| `KRISHA_MAX_PAGES` | 2 | Страниц выдачи за запуск |
| `KRISHA_MAX_CARDS` | 10 | Карточек за запуск |
| `KRISHA_PLAYWRIGHT` | выключено | Загрузка закрытой карточки браузером |

За запуск - не больше 30 запросов: обычный HTTP с User-Agent из `SAQ_USER_AGENT`, без cookie, перенаправления только на `https://krisha.kz/…`. Запрет robots.txt - ошибка "robots.txt Krisha запрещает …", а не пустая выдача.

**Проверка доступа SafeLine(HTTP 468).** Обход не выполняется.

- Закрыта карточка - запуск "частично", сохраняются данные из выдачи.
- Закрыта страница поиска - "нужно ручное действие", сбор остановлен: убедиться в обычном браузере, что сайт доступен, при необходимости увеличить `KRISHA_MIN_DELAY_S` или период, затем "Проверить подключение".
- `KRISHA_PLAYWRIGHT=1` - закрытая карточка загружается Playwright с выключенным JavaScript, проверка в ответе даёт ту же остановку. Playwright ставится отдельно, путь вживую не проверялся.

**Данные.** `window.data` разбирается JSON-декодером без выполнения JavaScript, по белому списку полей. Описание, ЖК, застройщик и документы - из разметки карточки; документы - заявление продавца, а не проверенное основание, и хранятся только в исходном снимке. Аккаунт публикации - "krisha.kz / <ЖК или тип продавца>". До 10 фото на объявление; заменённое фото - новая версия.

## 2ГИС

Геокодер 2ГИС(Catalog API 3.0, `items/geocode`) - геоданные, а не сбор рекламы: кандидаты адреса для карточки ЖК, объекта открытого реестра или объекта из рекламы.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DGIS_API_KEY` | - | Ключ API |
| `DGIS_QUOTA_LIMIT` | 900 | Запросов за период ключа |
| `DGIS_QUOTA_PERIOD_START` | - | Начало периода в кабинете 2ГИС, ГГГГ-ММ-ДД |
| `DGIS_DAILY_LIMIT` | 50 | Запросов в сутки по Усть-Каменогорску |
| `DGIS_CACHE_TTL_DAYS` | 7 | Срок хранения кандидатов, дней |

Квота считается до запроса, по отпечатку ключа: новый ключ считается заново, исчерпанная квота периода или суток - отказ 429 без обращения к 2ГИС. Локальный счётчик - оценка, точный расход - в кабинете 2ГИС. Демо-ключ проекта действует до 16.11.2026, 1 000 запросов за период. Ключ идёт параметром `key`, поэтому адрес запроса в журнал и ошибки не пишется.

**Сверка адреса.** Карточка ЖК или объекта реестра → "Сверка адреса в 2ГИС" → "Сверить адрес"; запрос по умолчанию - "Казахстан, Усть-Каменогорск, {адрес}", его можно изменить. Объект из рекламы сверяется так же(`POST /api/discovered/{id}/geo`) по названию ЖК и адресу из рекламы.

- Кандидаты - дом, город, корпус, точность и расстояние до точки карточки. Метка "рекомендуется" - только у единственного точного дома в городе и только подсказка: кандидат автоматически не выбирается.
- "Принять" кандидата; отметка "Перенести координаты в карточку ЖК" меняет координаты с записью "было → стало", а если точка карточки изменилась после сверки - 409. "Отклонить всех" - ни один не подходит.
- Сведения открытого реестра сверка не меняет. У объекта из рекламы координаты кандидата переходят в карточку ЖК при её создании - [FEATURES.md, "Проверка по рекламе и объекты из рекламы"](FEATURES.md#проверка-по-рекламе-и-объекты-из-рекламы).

**Кэш и лимиты.**

- Сверку запускает любой вошедший аналитик, "Обновить запрос" мимо кэша - только администратор; открытие карточки к 2ГИС не обращается.
- Тот же адрес в пределах срока кэша квоту не расходует; новый запрос по объекту - не чаще раза в 10 минут.
- 429 от 2ГИС - "пауза: лимит запросов" до `Retry-After`. Ответ неизвестного формата - 502, в кэш не попадает.
- Квота и кэш - `GET /api/geo/status`. Воркер раз в час удаляет устаревших кандидатов, решения аналитика остаются.
- Порядок координат: у 2ГИС `{lat, lon}`, у ЖК `{lat, lng}`. Подложка карты 2ГИС не подключена.

## OLX.kz

OLX Partner API с OAuth собственного аккаунта: доступ только к ресурсам этого аккаунта, чтения чужих объявлений нет. Статус - "подключено · ограничено", сбора публикаций у OLX нет.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OLX_CLIENT_ID`, `OLX_CLIENT_SECRET` | - | Выдаёт OLX после одобрения заявки |
| `OLX_REDIRECT_URI` | - | Callback URI из заявки, значение проекта - в `.env.example` |
| `OLX_SCOPES` | `read v2` | Права токена |

`OLX_REDIRECT_URI` - строго вида `https://<хост>/api/integrations/olx/callback`; значение другого вида не используется(предупреждение в журнале API, подключение "не настроено").

**Подключение.**

1. Ключи в `.env`, перезапуск API и воркера → "не подключён".
2. Туннель ngrok на порт API 8000(не 5180) с доменом из `OLX_REDIRECT_URI`: `ngrok http --url=https://<домен> 8000`. Через этот хост API отвечает только на путь обратного вызова - [SECURITY.md, "Сетевой периметр"](SECURITY.md#сетевой-периметр).
3. Режим администратора → "Подключить аккаунт OLX"(`POST /api/integrations/olx/start`) → войти на OLX и разрешить доступ. Ссылка одноразовая, 10 минут; state хранится как SHA-256 и привязан к отпечатку токена администратора, так как сессию браузера на домене туннеля проверить нельзя.
4. OLX возвращает браузер на `GET /api/integrations/olx/callback`: сервер проверяет state, обменивает код на токены, проверяет аккаунт(`users/me`) и показывает "OLX подключён: …"; событие - в журнале. Дальше туннель не нужен.

**Токены.** Хранятся только в БД, без шифрования([SECURITY.md, "Принятые риски"](SECURITY.md#принятые-риски)). Воркер раз в сутки проверяет подключение и обновляет токен доступа меньше чем за час до истечения; истёк refresh token(30 дней) - "Доступ OLX истёк - подключите аккаунт заново". "Отключить аккаунт"(`POST /api/integrations/olx/disconnect`) удаляет токены. Сменился адрес туннеля - обновить Redirect URI в кабинете OLX и `OLX_REDIRECT_URI`.

## Приём публикаций API

`POST /api/intake/publications` - вход для внешних сборщиков с нормализованными публикациями; подключение "Приём публикаций API". Маршруты - [API.md, "Приём и бот заявок"](API.md#приём-и-бот-заявок).

**Доступ.** `INTEGRATION_INGEST_TOKEN`, только `Authorization: Bearer`, проверяется до разбора тела. Нет токена на сервере - 503, нет заголовка - 401, неверный - 403. В статусе: неверный токен - "нет доступа", отклонённая публикация(409, 413, 422) или сбой сервера - "ошибка". Отказ 413 меняет статус только при верном токене: анонимный запрос с большим телом не переводит приёмник в "ошибку".

```bash
curl -s -X POST http://127.0.0.1:8000/api/intake/publications \
  -H "Authorization: Bearer <INTEGRATION_INGEST_TOKEN>" -H "Content-Type: application/json" \
  -d '{"platform": "tiktok", "externalId": "7000000000000000001", "account": "@example_developer",
       "publishedAt": "2026-10-16T11:10:23Z", "text": "Квартиры в новом ЖК, бронь 500 000 ₸",
       "media": [{"key": "cover", "url": "https://example.com/cover.jpg", "kind": "image"}]}'
# 201 {"status": "created", "adId": "…", "itemId": 1, "version": 1, "mediaQueued": 1, "analysisQueued": true}
```

| Поле | Формат |
|---|---|
| `platform` | Обязательно: `instagram`, `telegram`, `tiktok`, `krisha`, `olx`, `facebook` |
| `externalId` | Обязательно, до 128 символов, канонический вид: Telegram - "{ID канала}:{ID первого сообщения}"(вид `-100…` приводится к ID канала), Instagram и TikTok - до 32 цифр, Krisha - до 16 цифр, OLX и Facebook - буквы, цифры, `. : @ + = -` |
| `account` | До 255 символов |
| `url` | Ссылка http(s) до 512 символов или пусто |
| `publishedAt` | С часовым поясом |
| `collectedAt` | С часовым поясом, не старше 30 дней и не дальше 5 минут в будущем |
| `text` | До 100 000 символов, хранится до 20 000 |
| `price`, `reach` | Строка до 64 символов; целое от 0 до 2 147 483 647 |
| `media` | До 20 файлов: `key`(уникальный), `url` - только `https://`, `kind` - `image` или `video`, `mime` по желанию |
| `sourceId`, `externalRunId`, `raw` | `[a-z0-9_-]` до 32; до 64 символов; объект - исходный ответ источника |

Поля решений аналитика(`status`, `assignee`, `complexId`, `matchConfidence`, `linkConfirmed…`, `termsReview…`, `rejectedLinks`, `origin`, `source`, `id`) и неизвестные поля - 422.

| Ответ | Когда |
|---|---|
| 201 `created` | Новая публикация: версия 1, задание анализа |
| 200 `unchanged` | Повтор без изменений, копия не создаётся |
| 200 `updated` | Новая версия: решения аналитика сохраняются, анализ заново |
| 409 | Публикация с этим внешним ID собрана другим источником |
| 413 | Тело больше 2 МБ |
| 401, 403, 503 | Нет токена, неверный токен, приём не настроен |
| 422 | Ошибка формата или запрещённое поле |

**Хранение.** Публикации записываются от подключения "Приём публикаций API"; `sourceId`, `externalRunId` и заявленное `collectedAt` - в исходном снимке, время получения - серверное. Файлы по ссылкам скачивает задание анализа(этап `media`): только публичные адреса, с пределами размера и типа - [SECURITY.md, "Недоверенные данные"](SECURITY.md#недоверенные-данные). Статус: была публикация за 7 дней - "принимает публикации", иначе - "ожидает публикаций".

## Telegram-бот заявок

Приёмник заявок жителей для отдельного проекта `saq-telegram-bot`.

> **Контракт не сверен с адаптером `saq-telegram-bot`**(`integration/telegram_intake.py`): проекта бота в репозитории нет. Ниже - контракт приёмника; перед подключением бота маршруты, заголовок и формат тела сверяют с кодом адаптера.

**Доступ.** `SERVICE_API_TOKEN` - тот же секрет, что в настройках бота; `INTEGRATION_INGEST_TOKEN` не подходит. Заголовок `Authorization: Bearer` или `X-API-Key`, проверка до разбора тела. Ответы и отметки в статусе - как у [приёма публикаций](#приём-публикаций-api); успешный опрос статусов снимает "нет доступа". Свои переменные бот читает сам: `BOT_TOKEN`, `ADMIN_USER_IDS`, `ADMIN_CHAT_ID`, `SERVICE_URL`, `SERVICE_API_TOKEN`.

| Маршрут | Назначение |
|---|---|
| `POST /api/intake/telegram` | Заявка: `application/json` до 1 МБ без файлов или `multipart/form-data` с полем `payload`(JSON до 1 МБ) и повторяющимся полем `files` |
| `GET /api/intake/telegram/submissions/{externalId}` | Статус заявки; ID может содержать "/" |
| `GET /api/intake/telegram/updates?since=<ISO с поясом>&limit=1..500` | Заявки, полученные или изменившие статус строго позже `since` |

Файлы: до 10, каждый до 20 МБ, всё тело до 60 МБ; изображения JPEG, PNG, WEBP, GIF - не больше `MEDIA_MAX_IMAGE_MB`(по умолчанию 10 МБ), видео MP4, MOV; тип - по содержимому. Один неподходящий файл - отказ всей заявки(413, 415 или 422); часть без имени файла и лишние поля формы - 422.

| Поле заявки | Формат |
|---|---|
| `externalId` | Обязательно, 1-128 символов: буквы, цифры, `. : @ / + = -`; повтор - с тем же ID. Рекомендуется непрозрачный UUID заявки, а не "chat_id:message_id": иначе Telegram ID жителя попадёт в публикацию и журналы |
| `submittedAt` | С часовым поясом, по желанию |
| `platform` | `instagram`, `telegram`, `tiktok`, `krisha`, `olx`, `facebook`, `other`(по умолчанию) |
| `account` | Аккаунт рекламодателя со слов жителя, до 255 |
| `url` | Пусто или ссылка http(s) с хостом, до 512; с логином или паролем, неверным портом или символами `` \ < > " ` `` - 422 |
| `text`; `comment` | До 100 000 символов, хранится до 20 000; слова жителя, до 4 000 |
| `applicant` | `telegramUserId`, `chatId`, `username`, `name`, `phone` |
| `media` | Описание `files` по порядку, до 10: `key`(например `file_unique_id`), `fileName`, `mime` |

Ключ файла - `media[i].key` или содержимое: замена фото под тем же `externalId` - новая версия; повтор без `files` и `media` оставляет прежние файлы. Описанный, но не переданный файл помечается "Бот не передал файл". Поля решений аналитика и неизвестные поля - 422.

**Ответы.** Новая заявка - 201 `created`, повторная доставка - 200 `unchanged`, изменённая - 200 `updated`(новая версия). Статусы для жителя: `received` - "Заявка получена и ждёт проверки аналитиком", `in_review` - "Заявка на проверке", `confirmed` - "Проверка завершена: признаки нарушения подтверждены аналитиком", `dismissed` - "Проверка завершена: нарушение не подтверждено". Следующий опрос - с `since` = `updatedAt` последнего элемента(UTC с микросекундами), надёжнее с запасом в несколько секунд и без повторного сообщения жителю той же пары(`externalId`, `status`).

**Хранение.** Заявка проходит единый приём(пространство `tgbot`): публикация `source = bot`, "Новая", без привязки к ЖК, задание анализа. Данные заявителя и комментарий - только в `bot_submissions`, не в публикации, журнале и ответах API. Аккаунт и ссылка со слов жителя в сопоставлении с ЖК не участвуют и в Anthropic не уходят. Статус: была заявка за 7 дней - "принимает заявки", иначе - "ожидает заявок".

**`SERVICE_URL` бота.** Бот в Docker подключается к внешней сети `<проект>_frontend` этого compose-проекта(по умолчанию `codemasters8_frontend`; в ней есть `api`, но нет `db`) и обращается к `http://api:8000`, а не к `localhost`. Бот на этой машине без Docker - `http://127.0.0.1:8000`: порт API опубликован только на 127.0.0.1. Нужен ли префикс `/api`, решает адаптер. На один токен бота - один процесс long polling, без webhook.

### Подписки на районы

Доступ - `SERVICE_API_TOKEN`. Бот этих вызовов не делает: без его доработки предупреждения уходят только в канал.

| Маршрут | Назначение |
|---|---|
| `GET /api/intake/telegram/districts` | Районы ЖК для клавиатуры бота: `[{"district": "…", "complexes": 6}, …]` |
| `PUT /api/intake/telegram/subscriptions/{chatId}` | Заменить подписку: `{"districts": ["Ульбинский"]}`, `[]` или `["*"]` - все районы. Ответ - `{chatId, districts, everywhere, status}` |
| `GET /api/intake/telegram/subscriptions/{chatId}` | Текущая подписка; 404 "Подписки нет" |
| `DELETE /api/intake/telegram/subscriptions/{chatId}` | Отписка, 204 и при повторе; ожидающие доставки жителю - "Житель отписался до отправки" |

`chatId` - число Telegram(`^-?[1-9]\d{0,19}$`). Районы - без учёта регистра, до 50; неизвестный район - 422 со списком районов, лишние поля(имя, телефон) - 422. Хранятся только `chat_id` и район.

## Предупреждения жителям через Bot API

Отправка предупреждений в публичный канал ГАСК и подписчикам района в боте заявок(`backend/app/alerts.py`); не подключение-сборщик, состояние видно на `/residents`. Интерфейс - [FEATURES.md, "Предупреждения жителям"](FEATURES.md#предупреждения-жителям), маршруты - [API.md, "Предупреждения жителям"](API.md#предупреждения-жителям).

**Переменные.**

- `BOT_TOKEN` - токен бота заявок от @BotFather, тот же, что у `saq-telegram-bot`, вида `<до 20 цифр>:<20-100 символов A-Z a-z 0-9 _ ->`; токен другого вида не используется. Вызываются только `sendMessage`, `getMe`, `getChat`, `getChatMember`, без `getUpdates` и webhook: long polling бота не прерывается. Путь `/bot<токен>` в журналах маскируется.
- `TG_ALERTS_CHANNEL` - публичный канал ГАСК: `@имя`(или `t.me/имя`) либо ID `-100…`; бот - администратор канала с правом "Публикация сообщений". Пусто - только подписчики бота.
- Согласованию нужен `SAQ_ADMIN_TOKEN`, подпискам - `SERVICE_API_TOKEN`.

**Настройка.** Бот - в администраторы канала, `BOT_TOKEN` и `TG_ALERTS_CHANNEL` - в `.env`, перезапуск API и воркера, затем на `/residents` в режиме администратора - "Проверить бота и канал"(`POST /api/alerts/check`, без отправки сообщений).

**Согласование.** По ЖК - не больше одного предупреждения на согласовании(второе - 409). "Согласовать и отправить"(`POST /api/alerts/{id}/approve`) требует токен администратора; согласующий - не автор текста(без учёта регистра), иначе 409 "Согласует другой сотрудник". Без годного `BOT_TOKEN` - 503; нет ни канала, ни подписчиков района - 409 "Некому отправить". Получатели фиксируются при согласовании(подписчики района и "всех районов"); повторное согласование второй рассылки не создаёт.

**Отправка** - задание воркера `alert`(приоритет ниже проверок и выше сбора), до 5 попыток с паузой от минуты до часа. Доставки берутся по одной условным UPDATE "ожидает → отправляется". Сообщение - HTML: заголовок, текст, хэштег района, подпись "ГАСК ВКО · SAQ QURYLYS", без превью ссылок. Не больше 20 сообщений в секунду и 200 доставок за выполнение, остаток - продолжением задания.

| Ответ Telegram | Что происходит |
|---|---|
| 200 | Доставлено; у подписчика `chat_id` в доставке стирается, у канала сохраняется ссылка на пост |
| "bot was blocked by the user", "chat not found" и подобные | Не доставлено, подписка жителя снимается |
| 400 или 403 по каналу | Канал - "не опубликовано" с пояснением, подписчикам отправка продолжается |
| 429 | Пауза на `retry_after` без расхода попытки, доставка снова "ожидает" |
| Соединение не установлено, 5xx | Доставка снова "ожидает", повтор задания с паузой |
| Нет ответа после отправки(тайм-аут чтения, обрыв) | "Результат неизвестен - сообщение могло дойти", повторно не отправляется |
| 401 или 404(токен не принят) | Задание завершается, доставки ждут; после исправления токена - "Повторить отправку"(`POST /api/alerts/{id}/retry`) |

Доставка, оставшаяся "отправляется" после сбоя воркера, тоже не повторяется: житель не получит предупреждение дважды. Итог - "Отправлено", "Отправлено частично" или "Не отправлено" с числом получивших и причинами недоставки, событие журнала ЖК - от "Системы". Хранение подписок - [SECURITY.md, "Персональные данные"](SECURITY.md#персональные-данные).

## Ограничения и проверка вживую

"Вживую" - подключение работало с настоящим источником или клиентом; у сборщиков, 2ГИС и Claude результат есть в стартовом наборе `shared/snapshot`. Остальное проверено автотестами с заглушками - [DEVELOPMENT.md, "Тесты бэкенда"](DEVELOPMENT.md#тесты-бэкенда). Состояние конкретного развёртывания - страница `/sources` и `python -m app.integrations.smoke`.

| Подключение | Вживую | Ограничение |
|---|---|---|
| Instagram | да: сбор по расписанию 18.10.2026, 168 публикаций в стартовом наборе | Только аккаунты из списка; токен продлевают раз в 60 дней |
| Telegram-каналы | нет: нет авторизованной сессии | Только публичные каналы; правки - в окне `TG_EDIT_WINDOW` |

| Krisha.kz | да: 52 объявления, запуск "частично" - карточки за проверкой доступа | Карточки периодически закрыты SafeLine(HTTP 468); Playwright не проверялся |
| Telegram-бот заявок | нет: проекта бота в репозитории нет | Контракт не сверен; подписки бот не регистрирует |
| Приём публикаций API | да: локальным клиентом, в том числе в Docker на PostgreSQL | Решения аналитика через приём не передаются |
| 2ГИС | да: 3 принятые аналитиком сверки | Только геокодер; счётчик квоты - оценка |
| Claude(Anthropic) | да: 458 ответов `claude-sonnet-5-5` по собранным публикациям | Гипотезы, не решения; текст и OCR уходят в Anthropic |

## Что нужно от владельцев аккаунтов

1. **Meta** - пользовательский токен с разрешениями из раздела ["Токен Meta"](#токен-meta): долгосрочный или токен системного пользователя.
2. **Telegram** - выделенный аккаунт, его `TG_API_ID` и `TG_API_HASH`, код входа в течение 15 минут после `--send-code` и пароль 2FA, если включён.
3. **Apify** - API-токен и согласованный дневной лимит расходов.
4. **OLX** - одобрение заявки, `OLX_CLIENT_ID` и `OLX_CLIENT_SECRET`.
5. **Anthropic** - `ANTHROPIC_API_KEY`(необязательно), согласованный дневной бюджет и согласие на передачу текста публикаций в Anthropic.
6. **Бот заявок** - проект `saq-telegram-bot`: сверить контракт приёмника и добавить подписку на районы.
7. **Предупреждения жителям** - `BOT_TOKEN` бота заявок и публичный канал ГАСК, где бот - администратор с правом публикации.
8. **2ГИС** - ключ API и дата начала периода квоты.
9. **Krisha** - ничего: проверка доступа SafeLine - ограничение сайта, обход не выполняется.

Сервису нужны токены, ключи и сессии, а не пароли: разработчикам выдают роли в кабинетах Meta, Apify, OLX, 2ГИС и Anthropic.
